<h1>Stack knowledge belongs to Genesis</h1>
<p>
Vibe64 does not classify every repository into one framework adapter. It asks
Genesis for the selected project Stack and uses the returned portable contracts.
</p>
</section>

<section class="vibe-adapter-section">
<h2>What a Stack component may contribute</h2>
<div class="vibe-adapter-grid">
<article class="vibe-adapter-card">
<div class="vibe-adapter-card__top"><div class="vibe-adapter-icon">i</div><span>CONTEXT</span></div>
<h3>Description</h3>
<p>Concise technology context used only when that component is selected. A project can add to or override its Description, Guidance, Adoption, Post-change, and Deslop prose.</p>
</article>

<article class="vibe-adapter-card">
<div class="vibe-adapter-card__top"><div class="vibe-adapter-icon">S</div><span>STANDARD</span></div>
<h3>Agent Skill</h3>
<p>An optional authoritative Agent Skill directory, including its instructions, references, scripts, assets, and agent metadata. A component does not need a Skill to be selectable, and Genesis does not create substitutes for official technology guidance.</p>
</article>

<article class="vibe-adapter-card">
<div class="vibe-adapter-card__top"><div class="vibe-adapter-icon">Fn</div><span>STRUCTURE</span></div>
<h3>Indexers</h3>
<p>Language-aware extraction for Machine City and function lookup. Several compatible components can contribute indexers and duplicates are collapsed.</p>
</article>

<article class="vibe-adapter-card">
<div class="vibe-adapter-card__top"><div class="vibe-adapter-icon">✓</div><span>EVIDENCE</span></div>
<h3>Resources and verification</h3>
<p>Generic required inputs and an initial exact argument-safe command proposal. Selection materializes the proposal into the project-owned Stack; Genesis reports missing inputs and records successful verification against exact code and Stack hashes.</p>
</article>

<article class="vibe-adapter-card">
<div class="vibe-adapter-card__top"><div class="vibe-adapter-icon">↓</div><span>OPTIONAL</span></div>
<h3>Workspace setup</h3>
<p>An initial proposal for ordered argument-safe preparation commands, relative working directories, and abstract runtime requirements. Once materialized, the complete project section is authoritative; Vibe64 validates and executes it when preparation is requested.</p>
</article>

<article class="vibe-adapter-card">
<div class="vibe-adapter-card__top"><div class="vibe-adapter-icon">▶</div><span>OPTIONAL</span></div>
<h3>Output targets</h3>
<p>An initial proposal for exact commands, relative working directory, abstract runtime requirements, terminal or web presentation, and optional immutable downloads. The project owns the materialized section; Genesis starts nothing and Vibe64 retains all execution and presentation policy.</p>
</article>

<article class="vibe-adapter-card">
<div class="vibe-adapter-card__top"><div class="vibe-adapter-icon">◇</div><span>NEUTRAL</span></div>
<h3>No selected Stack</h3>
<p>A valid starting state. Genesis still provides its Blueprint, engineering profile, Program, workflow skills, prompts, Codex/OpenCode session guidance, and explicit cleanup contract without assuming a language or package manager.</p>
</article>
</div>
</section>

## Built-in components

The current Genesis Stack package provides components for Node.js, Vue, Python,
Java, C#, C and C++, PHP, Go, Rust, Ruby, Kotlin, Shell, MySQL, PostgreSQL,
JSKIT, JSKIT with MySQL, JSKIT with PostgreSQL, Laravel, Laravel with MySQL, and
Laravel with PostgreSQL. The language components select structural indexers for
JavaScript and TypeScript where relevant.

This list is Genesis package data, not a Vibe64 project-type whitelist. Use the
Genesis Stack listing for the exact version installed with Vibe64.
